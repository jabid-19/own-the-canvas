## Problem Statement

own-the-canvas ships 53 Canvas 2D effects. In 2026 any single effect is a prompt away: Claude/Cursor will write a decent MatrixRain in 30 seconds, and copy-paste catalogs (react-bits ~110 comps / ~30K stars, Aceternity, Magic UI) own the "drop-in effect" slot. Competing on effect count loses to both.

Code audit: `src/hooks/useCanvasSetup.ts` exists but **0 of 53 components use it**. All 53 `use*.ts` hooks run their own rAF loop and own ResizeObserver. Structurally the library is 53 standalone snippets, the exact thing AI commoditizes.

Target users: landing-page devs (want drop-in polish that's safe to ship) and creative coders (want an engine they can compose).

## What Makes This Cool

Effects that know the page. Sakura petals land on your real `<h1>`, slide off the edge of a CTA button, rain splashes on cards. Nobody ships this: the closest is Disintegrate (DOM to particles via html2canvas, no collision). One GIF of petals settling on a real hero section sells the library.

Underneath: one shared runtime that makes every effect production-safe for free. That runtime can't be copy-pasted per-effect, which is the moat.

## Constraints

- Zero runtime dependencies stays.
- Public props + `preset` API stays backward compatible. New behavior is opt-in.
- Canvas 2D only (no WebGL in this phase).
- Must stay SSR-safe (Next.js App Router): no `window`/`document` access outside effects.

## Premises (agreed)

1. The moat isn't more effects; a 54th effect is a prompt away.
2. The moat is a shared runtime: one loop contract, one page "world" (DOM element rects, scroll), one perf governor. Effects plug into it.
3. Existing effects migrate gradually; props/presets stay backward compatible.
4. The "whoa" demo is DOM-aware: particles land on and bounce off real page elements.
5. Prod hardening ships as runtime defaults, free for every migrated effect.

## Approaches Considered

- **A: World hook + 3 hero effects** (chosen). Detailed below.
- **B: `<Stage>` scene graph.** One canvas, all 53 effects as interacting layers with shared forces and an event bus. Deferred: big rewrite before anyone sees value, plugin-contract risk. A's runtime is its foundation.
- **C: `<Atmosphere>` page weather.** One page-wide product for falling-stuff effects. Deferred: narrow, and it's a thin wrapper once A exists. Good candidate for A's launch demo later.

## Recommended Approach: A

### 1. Make `useCanvasSetup` the real runtime

Extend `src/hooks/useCanvasSetup.ts` (no new hook):

| Behavior | Mechanism | Default |
|---|---|---|
| Pause when offscreen | `IntersectionObserver` on canvas; stop rAF when not intersecting, reset `lastTime` on resume so `dt` doesn't spike | on |
| Pause when tab hidden | `document.visibilitychange` | on |
| Reduced motion | `matchMedia('(prefers-reduced-motion: reduce)')`, live listener. `reducedMotion: "static"` renders one frame and stops; `"ignore"` opts out | `"static"` |
| DPR cap | `Math.min(devicePixelRatio, maxDpr)` | `maxDpr: 2` |
| FPS governor | Rolling mean of `dt` over ~60 frames. Mean > 22ms for 2s: `quality` steps down 0.25 (floor 0.25). Mean < 17ms for 5s: steps up. Passed to `onFrame` as 5th arg | on |
| dt clamp | `dt = Math.min(dt, 64)` so a resumed tab doesn't teleport particles | on |

| Overlay clear | When `overlay` is on, the runtime calls `ctx.clearRect` before `onFrame` and effects skip their `backgroundColor` fill (eng review D3) | overlay only |

`onFrame` signature becomes `(ctx, w, h, dt, frame)` where `frame = { quality, world, overlay }`. Extra arg is additive; existing callers unaffected.

New `onResize(w, h)` option, called after DPR is applied (eng review D5). Effects re-seed particles there instead of inside their own resize handler.

Effects use `quality` to scale their own budget (e.g. `activeCount = Math.ceil(dropCount * quality)`). The runtime never mutates effect state.

**Migration rule: physics scales by dt** (eng review D6). Every velocity/position/angle step multiplies by `k = dt / 16.67`. At 60Hz `k = 1`, so tuned visuals are unchanged; at 120Hz motion stops running 2x fast. Sakura today is frame-based (`p.y += p.vy`, `gravity * 0.016`, [useSakuraBlossom.ts:162-165](../../src/components/SakuraBlossom/useSakuraBlossom.ts)).

Delete the dead duplicate `CanvasSetupOptions` / `CanvasSetupResult` in `src/types/index.ts`; the hook file owns them (eng review D7).

```
 mount ──> parent? ──no──> bail
   │yes
   v
 size source: overlay ? window resize : ResizeObserver(parent)
   └─> applyDpr(min(dpr, maxDpr)) ─> onResize(w,h)
 rAF loop ─┬─ paused? (IO offscreen | tab hidden | reduced-motion static) ─> no frame
           └─ dt = min(now-last, 64) ─> governor.step(dt) ─> quality
                ─> overlay ? clearRect : (effect fills bg)
                ─> onFrame(ctx, w, h, dt, { quality, world, overlay })
 resume ─> lastTime reset (no dt spike)
 unmount ─> IO, RO, window/document listeners, matchMedia listener, rAF all released
```

### 2. World: DOM solids

New file `src/runtime/world.ts`. Module-level singleton (one per page, shared by all canvases). No React context.

- Opt-in marker: any element with `data-otc-solid`.
- Discovery: `MutationObserver` on `document.body` (subtree, childList, attribute filter `data-otc-solid`). Started lazily on first subscriber, disconnected when last unsubscribes.
- Rects cached in **page space** (`rect + scrollX/Y`), eng review D9. Re-measured only on window resize, MutationObserver hit, or a solid's ResizeObserver firing. Scroll is pure arithmetic (`page - scroll`), no `getBoundingClientRect` during scroll, so no layout thrash next to Framer Motion/GSAP rAF writers.
- `data-otc-solid="live"`: opt-in per-frame rect read for sticky/animated elements (and the workaround for nested scroll containers, see TODOS.md).
- API: `world.solidsFor(canvas): Solid[]` returns rects in that canvas's local CSS-pixel coords, filtered to those intersecting the canvas. `Solid = { id, x, y, w, h, el }` with a stable `id` per element.
- Hidden elements (`w === 0 || h === 0`) skipped.

Collision helper (pure function, same file): `collide(p, prevY, solids, restitution)` for a point particle `{x, y, vx, vy}`:
- Moving down and crossing a solid's top edge between `prevY` and `y` (segment test, so fast particles can't tunnel): snap to top, then rest (`restitution === 0`) or bounce (`vy = -vy * restitution`).
- Moving up through a solid: pass (no ceiling collision in v1).
- Side hits: reflect `vx`.

**Anchored rest** (eng review D2). A resting particle stores `{ solidId, offsetX }`, not absolute x/y. Each frame: `x = solid.x + offsetX`, `y = solid.y`. Consequences:
- Scroll / sticky / animated solids: petals ride along.
- `offsetX` outside `[0, solid.w]` (wind push, solid shrank): released as falling.
- Solid removed (SPA route change): released as falling.
- Pile-up on solids reuses Sakura's existing settle logic ([useSakuraBlossom.ts:150-195](../../src/components/SakuraBlossom/useSakuraBlossom.ts)) with a per-solid floor. No particle-particle stacking.

```
 falling ──crosses top edge──> restitution>0 ? bounce (falling) : resting{solidId, offsetX}
 resting ──each frame──> solid still exists && 0<=offsetX<=w ? follow solid : falling
 resting ──recycle (too many settled)──> respawn at top
```

### 3. Overlay mode

Collisions only make sense if the canvas covers the elements. Add `overlay?: boolean`: the canvas is **portaled to `document.body`** via `createPortal` after mount (SSR-safe, immune to transformed ancestors that break `position: fixed`), eng review D4. Styled `position: fixed; inset: 0; pointer-events: none; z-index` (`zIndex` prop, default `10`), sized from window resize. Background is cleared, never filled (D3). Without `overlay`, collisions still work for solids inside the parent container.

### 4. Migrate SakuraBlossom (PR1 scope, eng review D1)

- Move loop/resize/DPR to `useCanvasSetup`; delete its local rAF + ResizeObserver code. Petal re-seed moves to `onResize`.
- Extract pure `stepPetal(p, env, k)`; physics scaled by `k`.
- New props: `overlay?: boolean`, `collide?: boolean` (default `false`), `restitution?: number` (default 0), `zIndex?: number`.
- Use `quality` for active petal count.

Rain + Confetti move in PR2 (TODOS.md). Remaining 50 effects untouched in this phase.

## Tests (vitest + jsdom, full coverage per eng review D8)

Add to `src/docs/test-setup.ts`: controllable `IntersectionObserver` mock (tests can fire intersect/leave), `matchMedia` mock with `change` dispatch, and a manual rAF queue (`flushFrames(n, dtMs)`) for lifecycle tests. Keep the existing never-firing rAF as default so docs tests are unaffected.

- `src/runtime/collide.test.ts` (pure): lands on top edge; bounce with restitution; side hit reflects `vx`; upward pass-through; fast particle crossing the edge in one step still lands; no solids = untouched.
- `src/runtime/world.test.ts` (stubbed `getBoundingClientRect`): refcount starts/stops MutationObserver; add/remove `[data-otc-solid]` discovered; zero-size skipped; page-space cache + scroll arithmetic gives correct canvas-local coords; no rect reads during scroll (spy); `live` solids read every frame; `solidsFor` intersect filter; stable ids.
- `src/runtime/anchor.test.ts` (pure): resting follows solid move; released when offsetX past edge; released when solid removed.
- `src/hooks/useCanvasSetup.test.tsx` (renderHook): governor step down/up/floor/ceiling (pure fn); dt clamp at 64; offscreen pauses, resume resets lastTime; tab hidden pauses; reduced-motion `static` renders 1 frame then stops, live toggle; `ignore` keeps looping; `maxDpr` cap; `onResize` called after DPR; overlay portals to body and calls `clearRect`; unmount releases every observer/listener/rAF.
- `src/components/SakuraBlossom/stepPetal.test.ts` **CRITICAL regression**: at `k = 1`, `stepPetal` reproduces the pre-migration formulas exactly (60Hz visuals and presets unchanged); `k = 2` moves twice per step.

## Implementation Notes (PR1, as built)

Deviations from the plan above, each for a reason found while building:

- **Nested scroll containers pulled in (reverses D12).** The docs site scrolls `#main-content` via Lenis, not the window, so the hero demo would have shown floating petals. `world.ts` marks dirty on any element scroll (capture listener). Window scroll stays arithmetic.
- **`solidsFor` is not filtered to canvas bounds.** Filtering would release petals resting on a headline as soon as it scrolled out of view. Collision cost for a handful of solids is negligible.
- **Fewer files.** Pure logic (governor, collide, anchor) lives in `src/runtime/physics.ts` with one `physics.test.ts`. `stepPetal` is exported from `useSakuraBlossom.ts`, tested in `SakuraBlossom.test.tsx`. Overlay/inline canvas markup is shared via `src/runtime/RuntimeCanvas.tsx` so Rain/Confetti reuse it in PR2.
- **Hook returns a callback ref** (`canvasRef` setter + `canvas`), so the runtime effect re-runs when the overlay canvas appears via portal after mount.
- **Test mocks are local** to `useCanvasSetup.test.tsx` (queued rAF, IO, matchMedia). `test-setup.ts` only gained a never-matching `matchMedia` stub (which also fixed 3 `Layout` tests that failed on `main` because Lenis calls it) and `setTransform/rotate/quadraticCurveTo` on the canvas mock.
- **Recycle threshold uses the quality-scaled budget** (`target * 0.6`, equal to `petalCount * 0.6` at quality 1), otherwise at low quality every petal would settle and none would fall.
